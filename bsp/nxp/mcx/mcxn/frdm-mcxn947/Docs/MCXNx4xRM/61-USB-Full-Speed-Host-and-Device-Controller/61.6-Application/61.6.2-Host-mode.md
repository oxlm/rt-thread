## 61.6.2 Host mode operation examples

The following sections list the steps to perform USB host functions using the USBFS core. See the Universal Serial Bus , "Chapter 9 USB Device Framework" for more information. 

To enable Host mode and discover a connected device: 

1. Enable Host Mode (CTL[HOSTMODEEN] = 1). 

• Enable the pulldown resistors and disable the pullup resistors. 

• SOF generation begins. 

• USBFS initializes the SOF counter to 12,000 (corresponding to an interval of 1 ms between SOF frames). 

• To eliminate noise on the USB, write 0 to CTL[USBENSOFEN] to disable SOF packet generation. 

2. Enable the ATTACH interrupt (INTEN[ATTACHEN] = 1). 

3. Wait for the ATTACH interrupt (ISTAT[ATTACH]), which is signaled by a USB peripheral device pullup resistor changing the state of DPLUS or DMINUS from 0 to 1 (CTL[SE0] to J or K state). 

4. Check the state of CTL[JSTATE] and CTL[SE0]. If the connecting device is low speed (CTL[JSTATE] is 0), then: 

• Write 1 to ADDR[LSEN]. 

• Write 1 to ENDPT0[HOSTWOHUB]. 

5. Enable RESET (CTL[RESET] = 1) for 10 ms. 

6. Enable SOF packet to keep the connected device from going suspended (CTL[USBENSOFEN] = 1). 

7. Send the appropriate commands to the default control pipe of the connected device, to enumerate the attached device. 

## To complete a control transaction to a connected device:

1. Complete all the steps to discover a connected device. 

2. Set up the endpoint control register for bidirectional control transfers: ENDPT0[4:0] = 0dh. 

3. Place a copy of the device framework setup command in a memory buffer. 

4. Initialize current even or odd TX EP0 BDT to transfer the 8 bytes of command data for a device framework command (for example, get a device descriptor). 

• Write 0008_0080h to the BDT command word –Byte count to 8, and write 1 to OWN. 

• Set the BDT buffer address field (see Table 477) buffer address field to the start address of the 8-byte command buffer. 

5. Set the USB device address of the peripheral device in the address register (ADDR[ADDR]). After the USB bus reset, the chip's USB address is zero. The set address device framework command writes 1 to the chip USB address. 

6. Write Token (TOKEN) with a SETUP to Endpoint 0, the peripheral device default control pipe (TOKEN = D0h). 

• This initiates a setup token on the bus, followed by a data packet. 

• After completing the packets, return the device handshake in the BDT PID field. 

• When you write the BDT, assert a Token Done (ISTAT[TOKDNE]) interrupt. This completes the setup phase of the setup transaction. 

7. To initiate the data phase of the setup transaction (that is, to get the data for the GET DEVICE DESCRIPTOR command), set up a buffer in memory for the data to be transferred. 

8. Initialize the current even or odd TX EP0 BDT to transfer the data. 

• Write 0040_00C0h to the BDT command word – BC to 64 (the byte count of the data buffer, in this case), write 1 to OWN field, and set Data toggle to Data1. 

• Set the BDT buffer address field to the start address of the data buffer. 

9. Write Token (TOKEN) with an IN or OUT token to Endpoint 0 (the peripheral device default control pipe), and write an IN token for a GET DEVICE DESCRIPTOR command (TOKEN = 0x90). This initiates an IN token on the bus, followed by a data packet from the device to the host. 

After the data packet completes, write the BDT and assert a Token Done interrupt (ISTAT[TOKDNE]). For control transfers with a single packet data phase, this completes the data phase of the setup transaction. 

10. To initiate the status phase of the setup transaction, set up a buffer in memory to receive or send the zero length status phase data packet. 

11. Initialize the current even or odd TX EP0 BDT to transfer the status data. 

• Write 0000_00C0h to the BDT command word – BC to 0 (the byte count of the data buffer in this case), write 1 to the OWN field, and set the Data toggle to Data1. 

• Set the BDT buffer address field to the start address of the data buffer. 

12. Write Token (TOKEN) with an IN or OUT token to Endpoint 0 (the peripheral device default control pipe), and write an OUT token for a GET DEVICE DESCRIPTOR command (TOKEN = 10h). This initiates an OUT token on the bus, followed by a zero-len<sub>g</sub>th data packet from the host to the device. 

After the data packet completes, write the BDT with the handshake from the device, and assert a Token Done (ISTAT[TOKDNE]) interrupt. This completes the data phase of the setup transaction. 

To send a full speed bulk data transfer to a peripheral device: 

1. Complete all steps to discover and configure a connected device. Write Address (ADDR) with the address of the peripheral device. Typically, there is only one other device on the USB bus in Host mode, so it is expected that the address is 01h and must remain constant. 

2. Write 1Dh to Endpoint Control (ENDPT0 - ENDPT15) to enable transmit and receive transfers with handshaking enabled. 

3. Set up the even TX EP0 BDT to transfer up to 64 bytes. 

4. Set the USB device address of the peripheral device in the address register (ADDR[ADDR]). 

5. Write Token (TOKEN) with an OUT token to the desired endpoint. The write to Token (TOKEN) triggers the USBFS transmit state machines to begin transmitting the token and the data. 

6. Set up the odd TX EP0 BDT to transfer up to 64 bytes. 

7. Write Token (TOKEN) with an OUT token, as in 5. To achieve maximum throughput, you can queue two tokens simultaneously to allow the packets to be double-buffered. 

8. Wait for ISTAT[TOKDNE] interrupt. This indicates that one of the BDTs has been released back to the processor and that the transfer has completed. 

• If the peripheral device asserts NAKs, then USBFS continues to retry the transfer indefinitely without processor intervention (unless ENDPT0[RETRYDIS] is 1). 

• If ENDPT0[RETRYDIS] becomes 1, then return the handshake (ACK, NAK, STALL, or ERROR (fh)) in the BDT PID field. 

• If a stall interrupt occurs, then you must de-queue the pending packet and you must clear the error condition in the peripheral device. 

• If a Reset interrupt occurs (CTL[SE0] for more than 2.5 μs), the peripheral device detaches. 

9. After ISTAT[TOKDNE] interrupt occurs, return to step 2 to examine the BDTs and queue the next data packet.
